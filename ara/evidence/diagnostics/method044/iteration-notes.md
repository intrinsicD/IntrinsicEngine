# METHOD-044 campaign notes

All cells are local dirty-worktree diagnostics, not native performance or production-adoption claims. The task note freezes each round before its execution. Existing METHOD-042/043 files and production defaults were preserved.

- Round 1: scalar topology implementation, 64 seed patches, actual LSCM-gated unions. Original and repeat frog/sculpt results are both retained. The initial xatlas frog audit incorrectly treated any non-disk chart as invalid; its null aggregate distortion is an **incomplete audit**, not evidence of a bad native map. Round 2 evaluates that same non-disk chart with direct triangle intersection checks instead.
- Profiling is instrumented and cannot be compared as wall-clock performance. It identifies repeated scalar topology traversal as the dominant implementation cost. Round 1's `uv_solves` counter includes topology-rejected parameterization attempts; Round 2 separates actual solves, parameterization attempts and factorized degrees of freedom.
- Round 2: vectorized edge incidence and face-corner fan connectivity implement the same disk predicate. Frog/sculpt chart labels, UVs and rejection counts are unchanged. Tests compare scalar/vectorized predicates on 300 deterministic subsets. Held-out meshes, analytic controls and fourfold subdivision retain the quality bound. Tighter 1.25/1.35 settings are operating-point comparisons, not changes made to rescue invalid charts.
- Direct UV triangle overlap checks permit shared boundaries and use a normalized coordinate tolerance of `1e-10`; they are not exact-predicate certification. Whole-chart reflection is allowed; mixed orientation within a chart is not. Per-chart normalization removes uniform chart scale, so between-chart texel-density ratio is reported separately.
- Native bunny10k returns `success` but includes an invalid chart ID (`4294967295`), degenerate UV mapping and two detected positive-area intersections. This negative cell is retained. It has not been diagnosed or repaired and cannot support a blanket xatlas quality comparison. Frog's non-disk native chart has no detected overlap and contributes to its reported distortion.
- Round 3 initially called `PackCharts` immediately after `AddUvMesh` on frog/sculpt. Both calls failed explicitly with `ComputeCharts must be called first` and emitted no atlas. The adapter was corrected to call `ComputeCharts`, which identifies supplied UV components in this UV-only API (no 3D geometry is provided). Exact source-corner mapping and unchanged chart count are checked afterwards. These were integration repairs, not changed labels/UV solves.
- All ten distinct packed settings retained in this campaign pass their corresponding post-pack stretch limits. The two additional `*_final` runs regenerate the 1.35 examples with importable OBJ/MTL/checker texture exports. Packing changes UVs slightly through float/pixel sizing; it is not assumed to be an exact similarity transform. The requested resolution 1024 is an estimate, not an exact output dimension; actual dimensions are retained.
- Round 4 separates feature-aware growth from feature-biased merge ordering on all four original meshes. Each uses the same 64 geometric seed positions and unchanged quality gates. It is an attribution experiment, not evidence that one formulation globally dominates all other classical atlas methods.
- The initial full CPU gate selected 4308 CTest entries: zero failures, six capability/environment skips. Standalone diagnostic tests are separate from that count. No GPU, sanitizer, UI, native algorithm port, arbitrary remeshing or global seam-optimality claim is made.
- A full-source high-effort Claude request timed out after 150 seconds without a response. A smaller numerical/topology/audit excerpt and measured-results packet was then reviewed successfully at medium effort. The focused review found no blocking error; its open normalization check was resolved by inspecting the area-normalized geometry helper. This is not a full independent repository review or an independent experiment replay.
