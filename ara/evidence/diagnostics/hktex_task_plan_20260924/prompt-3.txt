# METHOD-048 — Full HKTex mesh authoring, compiled rendering and measured default adoption

## Goal

Implement Heat Kernel Textures for IntrinsicEngine triangle surfaces: native
reference preparation/evaluation/fitting, surface-constrained kernel optimization
and density control, saved assets, compiled CPU evaluation and Vulkan rendering, filtered
material sampling, runtime/editor authoring, and a calibrated multi-view acquisition
path. Evaluate the proposed optimizations individually before enabling HKTex as
the default generated continuous mesh-appearance producer.

Operator direction on 2026-09-24 explicitly selects this work despite the standing
Theme-I pause behind REVIEW-004. This note is **planned backlog work**, not an
implementation claim. Creating/reviewing the task does not start engine changes.
METHOD-047 supplies the existing atlas/property bake and inspection baseline reused
by S04/S11/S14; it is a retired prerequisite, not HKTex evidence.
`ParityProven` is cumulative in the repository taxonomy and includes Operational;
its listed signals include promotion to the default. S18 adds the product gate.
The micro profile does not relax CPU-reference-first, research evidence, full CPU,
sanitizer, Vulkan or fixed-revision review gates.

## Scope, formulation and closure

- The paper's complete core means anisotropic surface operators; spectral grid
  preparation/alignment/interpolation; continuous source/query evaluation;
  normalized heat and distance weighting; nonlinear kernel modulation; both
  neighbor-selection stages; color formation; Riemannian optimization with
  transported momentum; pruning, cloning/splitting; fitting existing texture or
  property targets; and calibrated multi-view albedo fitting. Merely loading
  externally fitted kernels or rendering fixed colors does not close the task.
- Native C++ implements the mesh/property/UV authoring and runtime path. Python,
  PyTorch, FAISS, digeo and Mitsuba are reference/optional acquisition tooling,
  never unconditional runtime dependencies. Native CUDA is not part of this task.
- Original HKTex's appearance evidence is albedo. Continuous scalar channels,
  object-space normals, robust input extensions and alternate heat generators
  are separately named adaptations with their own tests and diagnostics.
- Preserve authoritative scientific properties, categorical IDs, source topology,
  authored material interpretation and existing UV export/inspection capabilities.
  A requested HKTex fit may be rejected or explicitly fall back; neither outcome
  counts as an HKTex success. Exact properties need not become lossy kernels.
- S00–S18 below are required scope. An experimental candidate may finish with a
  reproducible rejection; its rejected selector must not become an advertised
  backend. The core method, native runtime integration and acquisition path may
  not be replaced by a negative experiment. S18 must record accepted promotion
  or a named blocking result; the umbrella remains open if default adoption is
  still the desired outcome and its gate has not passed. An operator-recorded
  rejection of default adoption may instead close at the actually achieved
  maturity with the failed goal explicit; the implementer cannot silently drop it.

  bounds; their exact order over stored canonical float64 inputs defines strict
  ranking (not incidental float64 summation order). Compare upstream with its own measured
  precision. Near-tie disagreement is logged, never an excuse for color error.
  Nonfinite, unstable denominator, invalid power domain and resource exhaustion
  are explicit outcomes. Stable IDs break exact ties in the native contract;
  the difference from upstream unspecified tie behavior is retained.
- Rank stability is a separate correctness axis: compute conservative arithmetic
  intervals for outer distances and inner contributions, certify ordering gaps,
  and refine ambiguous rankings with higher precision until resolved or explicitly
  unavailable. Exact ties use stable IDs. The deterministic strict mode keeps the
  oracle ranking and final-color gate; it cannot excuse O(1) color errors as ties.
  An interval-admissible comparison may diagnose upstream float32 results, but
  cannot satisfy strict parity. Record ambiguous/rank-mismatch pixel counts and
  final-color impact separately; S00's strict success cap is zero unresolved
  samples. No finite precision format alone proves ordering of arbitrarily close
  values. Query failure/capability rejection is truthful, not a successful fallback.
  S12 either implements bounded precision refinement or reports inability; adoption
  requires the preregistered eligible-domain coverage and visible-error gates.
- Exact-tie and refinement procedure: outer squared distances are polynomial in
  canonical stored vertex/source embedding and query operands; exact expansion
  or rational arithmetic decides their order, including exact equality followed
  by stable-ID order. Inner contributions include transcendental functions:
  identical selection-relevant expression operands (excluding color/source ID),
  or another proved symbolic equality, establish an exact tie. Otherwise use
  interval arbitrary-precision refinement up to S00’s finite cap; unresolved
  equalities remain explicit failures, not invented epsilon ties. Canonical query
  operands and coefficient generation identity must be serialized consistently.
- Refinement reads original canonical reference operands, never just rounded
  compiled coefficients. S05 can query S03’s retained inputs. S10/S12a may store
  optional refinement records sufficient to reconstruct both distance and heat/
  contribution expressions (embedding, source/grid spectral operands, normalizers
  and shape parameters as needed), counting all disk/CPU/VRAM and transfer costs.
  A compact payload without those records reports refinement unavailable when
  certification fails; such samples count against coverage, never strict success.
  Runtime loading does not rerun an eigensolver. S00 fixtures include proved exact
  ties, near ties and nontrivial undecidable-within-budget cases with distinct
  expected outcomes; S05 exact-tie tests pass via predicates, not infinite refinement.
