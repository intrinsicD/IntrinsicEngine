# METHOD-048 — Full HKTex mesh authoring, compiled rendering and measured default adoption

## Goal

Implement Heat Kernel Textures for IntrinsicEngine triangle surfaces: native
reference preparation/evaluation/fitting, surface-constrained kernel optimization
and density control, saved assets, native compiled CPU/Vulkan rendering, filtered
material sampling, runtime/editor authoring, and a calibrated multi-view acquisition
path. Evaluate the proposed optimizations individually before enabling HKTex as
the default generated continuous mesh-appearance producer.

Operator direction on 2026-09-24 explicitly selects this work despite the standing
Theme-I pause behind REVIEW-004. This note is **planned backlog work**, not an
implementation claim. Creating/reviewing the task does not start engine changes.
The micro profile does not relax CPU-reference-first, research evidence, full CPU,
sanitizer, Vulkan or fixed-revision review gates.

## Scope, formulation and closure

- The paper's complete core means anisotropic surface operators; spectral grid
  preparation/alignment/interpolation; continuous source/query evaluation;
  normalized heat and distance weighting; nonlinear kernel modulation; both
  neighbor-selection stages; color formation; Riemannian optimization with
  transported momentum; pruning, cloning/splitting; fitting existing texture or
  property targets; and calibrated multi-view albedo fitting. Merely loading
  externally fitted kernels or rendering fixed colors does not close the task.
- Native C++ implements the mesh/property/UV authoring and runtime path. Python,
  PyTorch, FAISS, digeo and Mitsuba are reference/optional acquisition tooling,
  never unconditional runtime dependencies. Native CUDA is not part of this task.
- Original HKTex's appearance evidence is albedo. Continuous scalar channels,
  object-space normals, robust input extensions and alternate heat generators
  are separately named adaptations with their own tests and diagnostics.
- Preserve authoritative scientific properties, categorical IDs, source topology,
  authored material interpretation and existing UV export/inspection capabilities.
  A requested HKTex fit may be rejected or explicitly fall back; neither outcome
  counts as an HKTex success. Exact properties need not become lossy kernels.
- S00–S18 below are required scope. An experimental candidate may finish with a
  reproducible rejection; its rejected selector must not become an advertised
  backend. The core method, native runtime integration and acquisition path may
  not be replaced by a negative experiment. S18 must record accepted promotion
  or a named blocking result; the umbrella remains open if default adoption is
  still the desired outcome and its gate has not passed.

### Spatial acceleration consideration

Index method-owned moving sources in the pinned biharmonic embedding, using
squared L2, configured nearest-k, source-ID stable ties and the same active set
as the fit. No radius surrogate or silent k truncation. Rebuild reference query
state when positions, anisotropy-dependent fields or active kernels change;
rebuild compiled lists when their frozen inputs change. Component-local behavior
is explicit. Candidate overflow increases work/subdivision within budget or
returns a budget failure. Update the spatial-index consumer inventory in S06.

## Impact protocol shared by every slice

- Each slice emits a result row with slice/config/source/fixture identity, actual
  backend/generator/representation, dependencies, correctness disposition and
  incremental plus cumulative deltas. Use schema-v2 manifests and retained
  failed attempts. A proposed test name or runner below is not already available.
- Freeze S00 controls and cohort before tuning: tiny analytic triangles/quads,
  sphere/torus, open boundaries, disconnected parts, skinny/degenerate faces,
  symmetric/eigenvalue-clustered meshes, ties/duplicate kernels, thin close sheets,
  sharp subtriangle decals and high-frequency images. Add representative licensed
  engine assets and separate fit/tuning from held-out views/assets.
- Runtime optimizations compare the **same frozen fit** to S03/S05; do not refit
  away compiler error. Fitter/generator variants use paired initial states,
  seeds, observations and stopping/budget policies; report changed fitted output.
- Record cold preprocessing, fitting, compilation, load/upload, warm evaluation,
  filtering and edit latency separately; source/cache/serialized/compiled/tree/
  filter/peak CPU/VRAM bytes; candidate mean/p95/p99/max; source/distance/tie/rank
  errors, final channel errors, seam/edge-band error and temporal flicker.
- Compare current atlas with its actual compression/mips/UV/gutter costs, direct
  attributes where semantically equivalent, and a named sampled surface baseline
  when available. No performance inference from operation counts or smoke runs.
- Before S04 campaign work, freeze numeric bounds in method.yaml and manifests:
  reference/compiled scalar residuals, per-channel output error, fit quality,
  angular normal error, footprint integration error and resource caps. Initial
  planning targets: normalized albedo compiler L∞ ≤ 1e-6 on CPU and ≤ 1e-4 on
  Vulkan; certified approximation budget ≤ 1/1024 per linear-albedo channel;
  angular normal error ≤ 0.5 degrees. These are proposed gates, not evidence.
  Raw scientific/categorical values require exact preservation. S00 must turn
  every remaining budget into finite values tied to the target device/scene;
  it cannot leave adoption limits as "acceptable" or retune them to pass.
- CPU float64 defines the semantic oracle; compare upstream with its own measured
  precision. Near-tie disagreement is logged, never an excuse for color error.
  Nonfinite, unstable denominator, invalid power domain and resource exhaustion
  are explicit outcomes. Stable IDs break exact ties in the native contract;
  the difference from upstream unspecified tie behavior is retained.

## Slice plan

All slice IDs are stable within METHOD-048. Each finishes with a fixed-revision
review, named tests, diagnostics and a small report; no deployment optimization
is enabled merely because its preceding slice passed.

### S00 — Paper intake, fixture bridge and executable contract
- [ ] Create the method package/manifest, pinned-source/license inventory and
  code-to-native formulation map. Export tiny upstream fixtures (operators,
  aligned eigenproperties, kernels, barycentric queries, intermediate and final
  outputs) with hashes. A pinned external environment is opt-in tooling only.
- [ ] Define sign/mass conventions, coordinate/color spaces, component/nullspace
  handling, anisotropy frames, eigenvalue multiplicity/alignment, zero modes,
  all epsilons/powers/clamps, outer/inner selection and error/status contracts.
- [ ] Freeze dataset splits, budgets and baseline configuration. Reserve public
  benchmark target `HktexBench`, stable IDs below and CTest prefix `Hktex.`.
  Gate: license/provenance and intermediate semantics reproducible; otherwise
  no parity claim. No future selector appears as an implemented backend.

### S01 — Surface/ALBO and deterministic spectral preparation (after S00)
- [ ] Assemble mass and isotropic/anisotropic operators from typed positions;
  tiny dense generalized-eigen reference first, explicitly bounded by mesh size.
  Implement grid alignment/interpolation and source normalization. Diagnose
  negative modes, clustered spectra, zero mass, missing frames and component modes.
- [ ] Tests: analytic planar/isotropic limits, residual `W Phi - M Phi Lambda`,
  mass orthogonality, eigenvector sign/subspace changes and upstream fixture deltas.
  Record preparation bytes/time and solver residuals under `rendering.hktex.prepare`.
- [ ] Gate: faithful operator/interpolation contract; no production fallback to
  unbounded dense solves. Optimized sparse preparation is owned by S15.

### S02 — Arbitrary surface points and geodesic optimizer primitives (after S01)
- [ ] Add/reuse barycentric source evaluation, surface gradients, triangle-edge
  crossing, constrained step/exp-map approximation and parallel momentum transport.
  Define vertex hits, boundary steps, step rejection and disconnected-sheet behavior.
- [ ] Compare directional derivatives to finite differences on smooth regions;
  transport norm/round-trip and flat-plane exactness tests; gradient/tie/nondifferentiable
  points have explicit rules. `rendering.hktex.surface_motion` records drift,
  rejected steps and cost. Gate: sources and momentum remain on the chosen surface.

### S03 — Full deterministic CPU evaluator (after S01/S02)
- [ ] Implement direct spectral heat, normalization, biharmonic distance/window,
  nonlinear modulation, exhaustive outer kNN, inner top contributions, compositing
  and final postprocessing. Freeze semantic tie order and trace intermediates.
- [ ] Test both intermediate fixture parity and final color; include zeros,
  negative spectral lobes, even/noninteger powers, duplicate sources, empty sets,
  K greater than source count, extreme sharpness and denominator floor crossing.
- [ ] `rendering.hktex.reference`: deterministic fixture results, upstream deltas,
  arithmetic/rank diagnostics. Gate: no optimized/compiled evaluator before this
  oracle and its correctness tests exist.

### S04 — Native fitting, constraints and density control (after S03)
- [ ] Implement the baseline objective/sampling, Adam-like shape updates, geodesic
  position/momentum updates, parameter constraints, initialization, error-driven
  clone/split, pruning and stopping; source IDs survive deterministic updates.
  Reuse exact property or authored-texture sampling; masks/coverage are not RGB.
- [ ] Tests: recover synthetic constant/gradient/decal targets; loss/gradient checks;
  source movement/splitting, no inactive-source leakage, deterministic seeds,
  cancellation and budget exhaustion. Compare trajectories only where algorithms
  and precision match; compare final error otherwise.
- [ ] `rendering.hktex.fit`: fit quality, time, active counts, samples and peaks
  versus fixed kernels/no density control. Gate: fitting produces reusable
  native kernels, not just an upstream subprocess result.

### S05 — Exact frozen-fit compiler and optimized CPU evaluation (after S04)
- [ ] Compile normalized heat to `H_s(b)=sum b_i A_si`; distance to
  `q_s(b)=sum b_i D_si-sum(i<j)b_i b_j E_ij`, sharing edge coefficients.
  Retain Gaussian-before-power order and all reference semantics. Baseline compiler
  may retain every source; no candidate or approximation shortcut yet.
- [ ] Compare face-major and shared-vertex storage at identical outputs; bounded
  streaming compile with explicit overflow. Independent tests expand original
  spectral expressions and query edges/interiors/subtriangle detail.
- [ ] `rendering.hktex.compile`: output/intermediate deltas, compile cost and total
  bytes vs S03 on the identical fit. Gate: CPU optimized parity before Vulkan.

### S06 — Certified candidates and fixed-rank cells (after S05)
- [ ] Bound squared distance on each cell; with kth-smallest upper bound U_k,
  discard only sources with lower bound > U_k. Keep ties and round conservatively.
  Recompute original outer/inner rankings at query; optional fixed-order cell
  specialization requires bounds over every possible competitor.
- [ ] Adaptive subdivision stops at configured memory/depth/work limits with an
  explicit failure or exact slower evaluation. No center-in-face shortcut.
  Update shared-index consumer documentation with the metric/reuse decision.
- [ ] Tests: exhaustive ranking against candidate sets, long thin cells, many
  overlapping/broad kernels, clones and cross-face ties; inspect proof obligations
  as well as samples. `rendering.hktex.candidates`: zero missed sources, list tails,
  bytes and warm cost versus S05; gate: output error unchanged.

### S07 — Certified final-color specialization (after S06)
- [ ] Bound complete color across possible rankings and clamps, including signed
  alpha and power domains. Use constant/base-color shortcuts only when the
  per-channel interval/error certificate fits the budget. Add low-order cell
  polynomials only if constant/exact cells leave a demonstrated cost problem.
- [ ] Tests: derivative/interval bounds, rounding, cancellation, selection jumps,
  negative lobes, unsafe-domain rejection and shared-edge continuity. Dense
  sampling supplements but does not establish a certificate. No arbitrary alpha cutoff.
- [ ] `rendering.hktex.specialize`: maximum measured and certified errors, certified
  area fraction, bytes and cost versus S06. Gate: explicit exact/approximate mode,
  validated conservative bounds; uncertified cells keep exact evaluation.

### S08 — CPU footprint oracle and filter contract (after S05)
- [ ] Define footprint/visibility/color-space semantics. Integrate final composed
  color, including rankings/clamps, across cells/faces with adaptive quadrature;
  independently converge supersampled renders. Distinguish empirical error
  estimates from certified interval enclosures.
- [ ] Tests: shrinking footprint → point limit; constant/integrable controls;
  tiny decals, high-frequency patterns, grazing ellipses, triangle/selection/occlusion
  boundaries. `rendering.hktex.filter_reference`: integration error vs convergence
  and cost. Gate: widening alpha or dividing filtered sums is not the oracle.

### S09 — Coarse moments, cross-face filtering and transitions (after S07/S08)
- [ ] Build coarse integral/moment caches of final color and a bounded cross-face
  hierarchy. Fully covered nodes use moments; partial coverage refines or bounds
  residuals. Near views retain analytic kernels. Count all cache/hierarchy bytes.
- [ ] Test anisotropic footprints, many tiny faces, minification/magnification,
  silhouettes with visibility controls, rank jumps and animated scale switches.
  Preserve `integral(P-C) ≤ epsilon` only under its normalized nonnegative filter
  assumptions; bound footprint approximation and integration separately.
- [ ] `rendering.hktex.filter`: flicker/error/storage/time against S08 and the atlas.
  Gate: no unbounded traversal; failed filter budgets retain explicit opt-in status.

### S10 — Native asset codec, packed layout and residency (after S05; filter extension after S09)
- [ ] Add versioned CPU asset payload for fit parameters, mesh/reference-domain
  identity, compiled coefficients/cells and optional filter cache. Store provenance,
  source/config hashes and regenerability requirements. Runtime rendering must load
  compiled payload without needing the fitting eigensolver/cache.
- [ ] Extend current assets/GpuAssetCache and RHI buffer/descriptors; define
  source-triangle/render-primitive mapping including seam splits, submeshes and
  instance bindings. Preserve deferred retirement and renderer operational checks.
- [ ] Tests: round trips, malformed sizes/indices/nonfinite input, hash mismatch,
  memory caps, stale handles and shared-material isolation. `rendering.hktex.asset`:
  serialized/loaded/peak residency bytes and cold load cost. Gate: no second owner.

### S11 — Runtime jobs, controls and mesh authoring UI (after S04/S10)
- [ ] Extend existing texture-production jobs, source capture, prepared readiness,
  serializable config, preview/apply, history, progress/cancel, and asset publication.
  Presets expose only implemented generator/evaluator/filter choices. Public
  bake/workspace interfaces stay compilation-local.
- [ ] Mesh panel supports fitting, inspection of kernels/support/error/budgets,
  pending/failed/stale states, representation provenance and explicit fallback.
  All compatible property names/provenances use identical binding rules.
- [ ] Tests: UI/agent/config parity; cancellation at each phase; source revision,
  topology edit, deletion, entity detach, scene close, out-of-order completion,
  undo/redo and restart/save/load. `rendering.hktex.lifecycle` records stage latency
  and cancellation responsiveness. Gate: no stale result may publish.

### S12 — Vulkan evaluation and visible material integration (after S05–S11)
- [ ] Port the already verified compiled evaluator/filter to Vulkan using existing
  material and residency boundaries. Prove face/barycentric addressing and derivative
  conventions; avoid extra vertex duplication solely for HKTex where possible.
  CPU remains the oracle; raster and compute paths report which actually ran.
- [ ] Offscreen readback tests of reference/exact/approximate/filtered outputs,
  forward/deferred lighting, instances, multi-material submeshes, nontrivial model
  transforms and resource retirement. Null or skipped Vulkan is not completion.
- [ ] `rendering.hktex.vulkan`: CPU deltas, full-frame and texture-stage GPU timestamps,
  p95 frame time, warm/cold VRAM and integration overhead at pinned scenes/devices.
  Gate: actual operational Vulkan, no portable speed claim from one device.

### S13 — Material channels and directional filtering (after S09/S12)
- [ ] Add explicit scalar/RGB/normal interpretation with range/units/encoding;
  share kernel support only where held-out error permits, otherwise channel-specific
  coefficients/supports. Preserve categorical and scientific exact-source routes.
- [ ] Native object-space normal reconstruction handles zero vectors, hemisphere
  errors and transforms. Implement/evaluate normal moment filtering against the
  actual engine BRDF; LEAN is a donor, not an assumed GGX conversion. Coordinate
  normal source authority with GRAPHICS-105 without creating a parallel pipeline.
- [ ] `rendering.hktex.channels`: scalar/RGB/normal/angular and rendered specular
  errors, per-channel incremental bytes/cost, grazing highlights and malformed
  encodings. Gate: no RGB clamp reused for unbounded/raw data; normals have their
  own oracle/readback tests rather than inheriting albedo parity.

### S14 — Edits, deformation, topology transfer and export (after S11–S13)
- [ ] Color edits reuse geometry coefficients; source/shape edits invalidate old
  and new ranking footprints. Rest-domain deformation is explicit; metric updates
  and remeshing trigger their own recapture/transfer/refit requirements.
- [ ] Implement local paint/update plus cancel/undo and bounded global fallback;
  preserve source correspondence and fit/compiled generation identities. Atlas
  export uses existing UV/bake machinery when required by the destination;
  authored UV inputs and existing atlas inspection remain available.
- [ ] `rendering.hktex.edit_export`: no stale generations, bounded transfer error,
  edit latency/affected records, deformation quality and exported appearance
  versus native. Gate: no "local update" claim if distant ranking regions change.

### S15 — Sparse preparation and fitting acceleration (after S04/S07)
- [ ] Implement a bounded production sparse partial generalized eigensolver
  route, reusing existing assembly/factorization; choose dependency versus minimal
  implementation after residual/orthogonality/scaling evidence. Stream/cache aligned
  grid data without hiding temporary memory or recomputation.
- [ ] Separately evaluate variable-projection/constrained color solves with
  fixed support, handling base-color rank ambiguity, clipping and nonlinear losses.
  Then evaluate deployment-cost-aware fitting (compiled bytes/work plus error),
  not kernel-count-only optimization. Separate toggles and paired baselines.
- [ ] `rendering.hktex.prepare_optimized`, `rendering.hktex.fit_variable_projection`,
  `rendering.hktex.fit_deployment_cost`: each reports matched error, total cost,

### S16 — Robustness and alternate generator experiments (after S15)
- [ ] Implement declared component/boundary policies and test weak/degenerate

  not silent source topology mutation. Scalar tufted-Laplacian robustness does
  not license arbitrary anisotropic/transport behavior.
- [ ] Isolate two candidate generators: sparse polynomial heat-operator actions
  on a consistent mass-scaled operator, and a residual-checked reduced basis.
  Each has a CPU reference/gradient check, separate identity and paired refit;
  neither is a parity optimization of the interpolated original by assertion.
- [ ] `rendering.hktex.robustness`, `rendering.hktex.generator_polynomial`,
  `rendering.hktex.generator_reduced`: record failures, accepted-domain coverage,
  residuals/positivity violations, fit quality and full preparation/runtime cost.
  Gate: evaluated/rejected variants are valid slice outcomes; unsupported source

### S17 — Calibrated multi-view acquisition (after S04/S10/S11)
- [ ] Implement a versioned observation contract: fixed mesh, cameras/intrinsics,

- [ ] Provide an opt-in pinned upstream Mitsuba/Dr.Jit acquisition adapter through

  rendering comparator. A future native differentiable renderer needs its own task.
- [ ] Transfer source/aligned spectral state or compiled coefficients plus exact

  Test actual image-fit → native load/compile → engine render on synthetic known
  albedo and a licensed calibrated example, with held-out image errors.
- [ ] `rendering.hktex.multiview`: actual authoring backend, held-out error, fit

### S18 — Independent ablations and default promotion (after all required slices)
- [ ] Freeze held-out corpus, current atlas configuration, devices/scenes and

- [ ] Only after those gates pass, change the generated continuous mesh-appearance
