## Method (what "proven" means here)

Three facts constrain the proof, and all greps covered both the body and the recursively included private headers (`Runtime.EditorFeatures.Internal.hpp` → `EditorGeometryHelpers.hpp`, `EditorFeatureCommands.Internal.hpp`, `EditorFeatureProperties.Internal.hpp`):

1. **Name visibility requires a direct (or re-exported) import.** Any name the TU *spells* must come from a visible import chain.
2. **Type completeness only requires reachability**, which is transitive through interface dependencies (exported or not). So a type that arrives via `auto`/member access stays complete as long as *some* retained import transitively imports its owner.
3. This is an implementation unit of `Extrinsic.Runtime.EditorWorkspaceSnapshots`; the interface (`.cppm:15-22`) imports only 8 modules non-exported, so none of the impl-unit imports are redundant through the interface. No import on lines 30/45/103/105-108 can be dropped on that basis.

So the removal test is: *no exported name of module M is spelled anywhere in the TU or its recursive headers.* I enumerated the export surface of each candidate and grepped for those names, plus every `Graphics::`-qualified and `Geometry::`-qualified use in the TU.

Unqualified lookup cannot reach `Extrinsic::Graphics`, `Extrinsic::Core::Dag`, `Extrinsic::Platform` or `Geometry::*` from inside `Extrinsic::Runtime::EditorFeatureDetail` (sibling namespaces), and the only namespace aliases in the TU are `Runtime.EditorWorkspaceSnapshots.Models.cpp:116-121` (`ECSC`, `Dirty`, `GS`, `Sel`, `G = Graphics::Components`, `A = Extrinsic::Assets`) — none aliases a candidate namespace.

## Tier 2 — plausible but NOT proven, do not ship in this pass

`Graphics.CameraSnapshots`, `Graphics.CurrentRendererContractAdapter`, `Graphics.GpuAssetCache`, `Graphics.RenderFrameInput`, `Graphics.RenderingContract` (lines 53-55, 59, 61): no exported name of theirs is spelled either. I did not do that and will not claim it. `Graphics.UvView`'s `EditorParameterizationUvViewCommandSurface` near-miss is exactly the kind of collision that makes namespace-name reasoning unsafe here.

## Expected effect (hypothesis until the compiler confirms)

Drops 8-9 direct BMI edges from the heaviest Editor TU. `Core.Dag.Scheduler` is the single largest win — it re-exports five partitions, so it is really six interface units. `EditorUiHost` re-exports `EditorWindowRegistry` (two units). `Platform.Window`, `GpuWorld`, `UvView`, `UvAtlas`, `Geometry.Graph` sit near the bottom of the graph and pull RHI/geometry closures behind them. Realistically this is a rebuild-fan-in reduction (edits to Dag/Platform/UvView stop invalidating this TU) more than a big single-TU wall-clock win; I would not promise a number.
