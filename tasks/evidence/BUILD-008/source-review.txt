Verdict: the change is correct and the evidence supports the stated claim. No blockers.

### Newline / byte-identity
- `[=[` followed immediately by a newline: CMake discards that first newline, so content begins at `#define TINYGLTF_NOEXCEPTION` — no leading blank line. The closing `]=]` sits on its own line, so the final `#include <tiny_gltf.h>` keeps exactly one trailing `\n`. Byte-for-byte identical to the old five `file(WRITE)` fragments.
- `NEWLINE_STYLE UNIX` pins LF rather than relying on the platform default, matching the literal `\n`s it replaces. No conflict with `@ONLY` (the documented exclusion is `COPYONLY`, not `@ONLY`).

### `@ONLY`
- Correct and defensive. Bracket arguments suppress expansion at *argument* evaluation, but `file(CONFIGURE)` still performs `configure_file` substitution on the content; `@ONLY` restricts that to `@VAR@`. The content has neither `@…@` nor `${…}`, so the output is unchanged today, and `@ONLY` keeps a future `${...}` in the snippet from being silently eaten.
- No `#cmakedefine` lines present, so the other configure-time rewrite rule is inert.

### mtime / idempotence
- `file(CONFIGURE)` writes via a temp file and copy-if-different, so an unchanged reconfigure leaves the inode's mtime alone — which is precisely what the old `file(WRITE)` did not do.
- Evidence is consistent with that and is the right shape: baseline shows identical `generated_sha256` with mtime advancing `…781642008709 → …881890598406`, and `ninja -d explain` names the mtime (not content) as the sole dirtying reason, then scans/compiles/links. Final shows mtime pinned at `…881890598406` and `ninja: no work to do`. `all_compile_commands_sha256` and `tinygltf_producer_commands_sha256` are identical across all four samples, so flags and the output path are demonstrably preserved. The initial dry-run correction (glob re-check masking the producer) is the right diagnosis; `VerifyGlobs` is still the only dirty edge in the final receipt, and it terminates without touching the producer.

### Repair path
- Corrupting the file and reconfiguring exercises the real code path: `file(CONFIGURE)` runs unconditionally on every configure, compares content, and rewrites on mismatch. The restored bytes are compared against the pre-corruption bytes, and mtime is deliberately discarded there — correct, since repair *should* move mtime.
- The generated content is backend-independent, so comparing a null-headless-era sample against a post-Vulkan-configure sample is sound.

### Inventory preservation
- `_generated_source_sample` is kept out of `Inventory`, so `assert_inventory_equal` and the cross-tree fresh-vs-fresh and explicit-vs-auto comparisons are untouched. Sampling happens after the fresh snapshot and before the reconfigure snapshot, so the added assertions cannot perturb ordering of the existing checks.
- Docs are scoped to what the tests actually assert — bytes, mtime, repair — with no speedup or sanitizer claim. Accurate as written.

### Non-blocking notes
1. `_generated_source_sample` now hard-requires the file in every configured tree, which silently couples the test to the `if(NOT TARGET tinygltf)` guard in `Dependencies.cmake`. If a future vcpkg port ever exports a real `tinygltf` target, the generator is skipped and the test fails with "generated dependency source is missing" rather than anything informative. Worth a comment at the guard, not a change here.
2. Repair is only covered under a *backend-transition* reconfigure. It is the same code path as an unchanged reconfigure, so coverage is adequate, but an unchanged-reconfigure repair case would be the more direct statement of the invariant if you ever extend this.
3. `file(MAKE_DIRECTORY)` is now redundant (`file(CONFIGURE)` creates parent directories). Harmless; leaving it is fine.
