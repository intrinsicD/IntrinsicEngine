**Parse-vs-ownership discrimination is genuinely tested.** `HasDiagnosticInState` matching on code *and* state is the right discriminator given the shared codes. `Unknown`/`Generated` → `UnsafeBindingDomain`/**Invalid** with an explicit negative assertion on the Unsupported variant; lowercase `scene` → `UnsafeBindingDomain`/**Unsupported**. Drift protection is sound in both directions: parsers derive from `ToString`, and the 49 literal expectations plus 7 invalid-sentinel checks fail loudly if a spelling moves.

`ConfigWithToken` wrapping the needle in quotes is what makes single-token replacement safe (`"Preview"` cannot hit `current-renderer.preview-output`, `"Buffer"` cannot hit `"ReadbackBuffer"`, `"Color"` cannot hit a lowercase `"color"` name), and the uniqueness `EXPECT_EQ(..., npos)` turns any wrong assumption about the fixture into a visible failure rather than a silent mis-target.

### Optional nits (none blocking)

1. `TokenSpellingsFallBackToUnknownForInvalidEnumValues` casts `200` into all seven enums. This is well-defined and UBSan-clean only if each enum has a fixed underlying type; the `std::uint8_t` literal suggests the author confirmed that. If any of them (e.g. two-enumerator `InteractionMode`) lacks a fixed underlying type, its value range is 0–1 and `-fsanitize=enum` would flag the cast. Worth a glance at the declarations if sanitizer builds are in CI.
2. `Test.RenderRecipeConfig.cpp` gains `std::any_of` and `std::size_t` but no include change, unlike `Test.RenderingContract.cpp` which added `<cstdint>`. Almost certainly already transitively present; the build will say so either way.
3. The `unknownValueType` case asserts the parsed value and the absence of a schema diagnostic but never pins `IsConfigUsable`. Pinning it would complete the "accepted spelling, ownership decides" story for value types the way the domain cases do.
4. Domain parse failure surfaces as `UnsafeBindingDomain`/Unsupported while value-type parse failure surfaces as `InvalidSchema`/Unsupported. Pre-existing and now documented by the test — a one-line comment on the asymmetry would help the next reader.
5. `ConfigWithToken`'s second parameter is indented one column past the opening paren.
6. `RenderRecipeEditorModelListsDeclaredRecipeControls` now mutates `BaseViewOutput` to non-default values inside a test whose stated subject is declared recipe controls. The five field checks are the right checks; a separate case would keep the subject narrow.
