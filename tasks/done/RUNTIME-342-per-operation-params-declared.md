## Goal
- M2 target "100 % of MCP tools are generated" (`ARCH-020` row 3): 46 of 48 after `RUNTIME-341`.
  `run_operation` and `preview_operation` share one schema: `operation` (every configured
  operation's name), `entity`, `params` (an open object) and `allOf` with one `if`/`then` per
  operation that has params: when `operation` is that name, `params` follows the schema generated
  from the operation's field table (`ParamsSchema`). The params schemas are generated already;
  the envelope and the `if`/`then` assembly are hand-written strings. After this slice: 48 of 48.

## Plan
1. **Open object**: an `Object` field without member fields (`Fields == nullptr`) generates
   `{"type":"object"}` only, without `properties` and `additionalProperties`: any object, which
   is what `CheckField` already accepts for an Object (its owner checks the members). No existing
   Object lacks fields (all six have them), so section schemas are unchanged.
2. **Argument cases**: `ArgumentsSchema` takes a fourth, optional parameter, the cases
   (`std::span<const ArgumentCase>`; `ArgumentCase` = argument name, value token, the property
   that depends on it, and that property's schema as generated JSON): when given, the schema gets
   `"allOf": [{"if": {"properties": {<argument>: {"const": <value>}}, "required": [<argument>]},
   "then": {"properties": {<property>: <schema>}}}, ...]` in the given order. The schema is
   generated by its owner (here `ParamsSchema` of the operation's field table, unchanged), never a
   literal; the comment on `ArgumentCase` says so.
3. **Tools**: `operation` (StringEnum, every configured operation's name in table order, from one
   helper that also serves the mesh-field aliases' list, its description, required), `entity`
   (`EntityArgument(false, ...)` with its current description), `params` (Object without fields,
   its description); cases from the configured operations with a params schema. Handlers
   unchanged. `Schema()` and the `ToolSchema` constructors from text lose their last users and are
   deleted; every production caller then takes its schema from `ArgumentsSchema` (the remaining
   `(text, declared)` constructor does not enforce that, O2). Capture and Diagnostics register
   generated ones too. The `Object` enumerator's comment states the no-fields meaning (O1).
4. **Baseline**: both hand-written schemas (registry dump at `36dd1fc81`; since then only this
   series' commits, none touching configured operations or their params tables) join
   `tests/data/agent_declared_tool_schemas.json`; count pin 46 → 48. Like style table rows, a
   field an operation's params table gains later is left out of the comparison; every baselined
   field of every params body is compared whole (B1: dropping whole bodies would hide a lost bound).
   At the conversion all 48 schemas were also compared in full once (dump).
- Not in this slice: generated handlers; the editor panels.
